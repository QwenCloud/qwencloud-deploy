# Remote Update Script Template (Executed on ECS)

`update_app.sh` executes the following script on ECS via Cloud Assistant RunCommand.
The Agent does not need to know the exact script content (auto-generated by `update_app.sh`); this document is for debugging reference only.

---

## App Update Flow

`update_app.sh` dispatches by the `app_type` in the state file, generating a
completely different update script:

| app_type | Update mechanism |
|----------|------------------|
| `systemd` | Two-phase atomic directory swap + `systemctl restart` (see "systemd" below) |
| `docker`  | `docker load` / `docker compose up` (see "docker" below) |

---

## systemd Update Flow (Two-Phase Atomic Swap)

### Phase 1: Preparation (service keeps running)

```bash
STAGING_DIR=/opt/qwencloud.staging
rm -rf "$STAGING_DIR" && mkdir -p "$STAGING_DIR"

# Download + integrity check
curl -fsSL '<APP_URL>' -o "$STAGING_DIR/app.tar.gz"
tar -tzf "$STAGING_DIR/app.tar.gz" >/dev/null
tar -xzf "$STAGING_DIR/app.tar.gz" -C "$STAGING_DIR"
rm -f "$STAGING_DIR/app.tar.gz"
```

#### Per-app_type Dependency Pre-install

| app_type | Pre-install Command (run in staging dir) |
|----------|------------------------------------------|
| systemd (runtime=python) | `pip download -d /tmp/qwencloud-pip-cache -r requirements.txt` |
| systemd (runtime=node) | `yarn install --production` |
| systemd (runtime=none) | None (static binary) |
| systemd (runtime=java) | None (fat jar) |

### Phase 2: Atomic Swap (downtime window)

```bash
systemctl stop qwencloud-app || true
# Keep the old version for rollback (drop the previous backup first)
rm -rf /opt/qwencloud.prev
if [ -d /opt/qwencloud ]; then mv /opt/qwencloud /opt/qwencloud.prev; fi
mv "$STAGING_DIR" /opt/qwencloud

# Offline dependency install (Python only, using Phase 1 cache)
pip install --no-index --find-links /tmp/qwencloud-pip-cache -r requirements.txt

systemctl restart qwencloud-app
```

### Health Check (auto-rollback on failure)

```bash
APP_PORT=$(sed -n 's/^Environment=PORT=//p' /etc/systemd/system/qwencloud-app.service | head -1)
APP_PORT=${APP_PORT:-8080}
sleep 3
for i in $(seq 1 15); do
  curl -sf -o /dev/null --max-time 5 "http://localhost:${APP_PORT}/" && exit 0
  sleep 2
done

# Health check failed -> roll back to /opt/qwencloud.prev,
# keep the bad artifact at /opt/qwencloud.failed for debugging
systemctl stop qwencloud-app || true
rm -rf /opt/qwencloud.failed
mv /opt/qwencloud /opt/qwencloud.failed || true
mv /opt/qwencloud.prev /opt/qwencloud
systemctl restart qwencloud-app
exit 1
```

## docker Update Flow

Uses state fields: `app_mode` (`docker-image` / `docker-compose`),
`app_image_name` (image name:tag), `app_port` (health check / port mapping).
The image/context is self-contained, so there is no dependency pre-install phase.

### docker-image mode

```bash
STAGING_DIR=/opt/qwencloud.staging
rm -rf "$STAGING_DIR" && mkdir -p "$STAGING_DIR"
curl -fsSL '<APP_URL>' -o "$STAGING_DIR/app.tar.gz"
tar -tzf "$STAGING_DIR/app.tar.gz" >/dev/null
tar -xzf "$STAGING_DIR/app.tar.gz" -C "$STAGING_DIR"   # extracts image.tar

# Record old image ID (for rollback) -> load new image
PREV_IMAGE_ID=$(docker images -q '<IMAGE_NAME>' | head -1)
echo "$PREV_IMAGE_ID" > /opt/qwencloud.prev-image
docker load -i "$STAGING_DIR/image.tar"

# Ensure systemd unit exists (may be missing on first hot update) -> atomic dir swap -> restart container
# unit content matches first-boot templates/userdata/docker.sh
rm -rf /opt/qwencloud.prev
if [ -d /opt/qwencloud ]; then mv /opt/qwencloud /opt/qwencloud.prev; fi
mv "$STAGING_DIR" /opt/qwencloud
systemctl restart qwencloud-app
```

### docker-compose mode

```bash
# staging download/verify same as above (artifact has docker-compose.yml + build context/image)
# stop old compose -> atomic dir swap -> start new compose
(cd /opt/qwencloud && docker compose -f docker-compose.yml down) || true
rm -rf /opt/qwencloud.prev
if [ -d /opt/qwencloud ]; then mv /opt/qwencloud /opt/qwencloud.prev; fi
mv "$STAGING_DIR" /opt/qwencloud
cd /opt/qwencloud
[ -f /etc/qwencloud/db.env ] && cp /etc/qwencloud/db.env ./.env
docker compose -f docker-compose.yml up -d --build
```

### Health Check (auto-rollback on failure)

```bash
APP_PORT=<app_port, default 8080>
sleep 3
for i in $(seq 1 15); do
  curl -sf -o /dev/null --max-time 5 "http://localhost:${APP_PORT}/" && exit 0
  sleep 2
done

# On failure:
#   docker-image   -> docker tag old image ID back to <IMAGE_NAME>, restore old dir, systemctl restart
#   docker-compose -> restore /opt/qwencloud.prev dir and docker compose up -d --build
# The bad artifact is kept at /opt/qwencloud.failed for debugging
exit 1
```

## Static Update Flow (Zero Downtime)

```bash
STATIC_STAGING=/var/www/static.staging
rm -rf "$STATIC_STAGING" && mkdir -p "$STATIC_STAGING"

curl -fsSL '<STATIC_URL>' -o /tmp/static.tar.gz
tar -tzf /tmp/static.tar.gz >/dev/null
tar -xzf /tmp/static.tar.gz -C "$STATIC_STAGING" --strip-components=0
rm -f /tmp/static.tar.gz

rm -rf /var/www/static
mv "$STATIC_STAGING" /var/www/static
nginx -t && systemctl reload nginx
```

## Cloud Assistant Invocation

```bash
aliyun ecs RunCommand \
  --RegionId "$REGION" \
  --InstanceId.1 "$INSTANCE_ID" \
  --Type RunShellScript \
  --CommandContent "$SCRIPT" \
  --Timeout 300
```

Poll status: `aliyun ecs DescribeInvocations --InvokeId "$INVOKE_ID"`
- `Finished` / `Success` → success
- `Failed` → get `DescribeInvocationResults` for error output (base64 decode)
- Timeout limit: 5 minutes

## State File Update (handled automatically by script)

On success `update_app.sh` auto-writes:
- `updated_at`: UTC timestamp
- `current_artifact_urls`: new artifact signed URLs
